# 子平八字 AI 公式书：使用指南（引擎 V1.4）

这是一套**可执行的传统命理规则说明和参考程序**，不是已经通过科学验证的现实人生预测器。

## 文件用途

- `子平八字_AI公式书_V1.0.pdf`：适合阅读、讨论、打印的 12 页版本。
- `子平八字_AI公式书_V1.0.docx`：可编辑、继续研究古籍与扩充规则的版本。
- `子平八字_AI公式书_V1.0.md`：AI 容易读取的公式书原始文本。
- `rules.json`：确定性表、十神定义、格局候选条件与出处。
- `bazi_engine.py`：仅依赖 Python 3.9+ 标准库的参考实现。
- `terms_1900_2100.json`：**V1.1 新增**。由 JPL DE440s 星历计算的 1899-02 至 2101-01 全部十二「节」交节瞬间，引擎默认加载。
- `generate_terms.py`：**V1.1 新增**。重新生成上表的脚本（需 `pip install skyfield` 与 de440s.bsp；引擎本身仍只用标准库）。
- `terms_2024_example.json`：北京市文物局公布的 2024 交节时刻，用于与星历表交叉核对。
- `sample_input_birth.json`：出生日期输入示例。
- `sample_input_pillars.json`：直接输入四柱的示例。
- `sample_output.json`：可审计的完整机器输出。
- `sample_input_range.json` / `sample_report_range.md`：**V1.1 新增**。出生时刻只知区间时的并列盘示例。
- `sample_report.md`：**V1.1 新增**。按 A–H 固定次序的确定性文字报告。
- `test_bazi_engine.py`：48 项规则与历法边界测试（含 1900–2100 全区间抽样、四张古籍表对原文的逐格校验）。
- `AI_执行指令.md`：给语言模型的标准执行约束。
- `generate_rules.py`：生成规则表与示例节气文件的脚本。
- `classic_tables.py`：**V1.2 新增**。人元司令、旺相休囚死、十二长生、穷通宝鉴调候四张表的数据源，由 `generate_rules.py` 写入 `rules.json`。
- `verify_against_references.py` / `verification_report.md`：**V1.3 新增**。用 lunar_python、sxtwl 两个第三方库批量对照四柱、十神、藏干、十二长生、交节、起运。
- `sources/`：**V1.2 新增**（V1.3 增《三命通会·卷三》）。维基文库《穷通宝鉴》《三命通会·卷二》原文快照（带修订号），表中每条数据都能对回原文行。

## 直接使用

先解压文件，进入所在目录。按以下命令运行：

```bash
# 直接给出生时刻（默认使用 1900–2100 星历交节表），输出文字报告
python3 bazi_engine.py --birth 1990-05-17T08:30:00+08:00 --gender female --luck-policy LUCK-P1 --format markdown

# 只给四柱
python3 bazi_engine.py --pillars 甲辰,丙寅,戊戌,庚申 --format markdown

# JSON 输入（可含 birth_time / birth_time_range / pillars），输出完整审计 JSON
python3 bazi_engine.py --input sample_input_birth.json --terms terms_2024_example.json --output output.json
python3 bazi_engine.py --input sample_input_range.json --format markdown

python3 -m unittest -v test_bazi_engine
```

建议把 Markdown 公式书、`rules.json` 和 `sample_output.json` 一起提供给 AI，再让 AI 解释其中的推理链。日期计算以程序输出为准，不让语言模型随意凭字面计算。

`--format markdown` 输出的报告每一句都由模板从 JSON 生成，可以直接作为「解读」交付，不需要语言模型再加工。

## V1.3 新增：月令取格规则与第三方对照

**取格 G-200**（《子平真诠》通行次序，`rules.json` → `geju_selection`），按固定顺序只走一条路径：

| 规则 | 条件 | 结果 |
|:--|:--|:--|
| G-201 | 月支为日干之禄（L-305，《三命通会·论十干禄》） | 建禄格，另取透干财官杀食伤 |
| G-202 | 阳干，月支为羊刃（禄前一辰，五阴干无刃） | 阳刃格，另取 |
| G-203 | 月令本气为比劫 | 月劫：先取月中透出的非比劫藏干，否则另取 |
| G-204 | 本气透出 | 本气十神为格；他干兼透者并列 |
| G-205 | 本气不透、中余气透出 | 透出者为格（多个则并列），本气保留 |
| G-206 | 藏干全不透 | 本气为格，标「未透」 |
| G-207 | 月支入完整三合/三会、局五行异于本气 | 追加会局候选（只给十神类别），待审 |

取格只产生候选，不判成败清浊。测试中另写了一份独立参考实现，对 6 万个穷举组合与 2 万个随机命盘逐一比对。

**夜子时政策** `late_zi_hour_stem`：在 00:00 换日下，23:00–23:59 的时干可按当日（`same_day`，默认）或按次日（`next_day`，夜子时派，与 lunar_python sect=2 相同）。

**第三方对照结论**（`verification_report.md`，2 万随机样本）：四柱、十神、藏干、十二长生、起运与 lunar_python 全部一致；交节时刻 1900–2030 年最大差 45 秒，2080 年后因 ΔT 外推最多差约 2 分钟（引擎均已标交节临界）；sxtwl 等按日换月的工具在交节当天会给出不同的月柱。

四张表都只**查表**，不加权，也不进入 G 规则。表中的版本差异（如人元司令墓库取阳干、十二长生「阴阳同生」口径）都写在 `rules.json` 的 `notes` 里，不暗中折中。

**假设层 STRENGTH-H1**：帮身（比劫印）/全部的加权比值。权重由编者设定，**没有古籍依据**，输出时用 9 组权重做敏感性检验；只要标签随权重变化就标 `unstable`。它只出现在报告 G2 节，不被任何规则引用。

### 星历交节表的精度说明

与北京市文物局 2024 表逐项比对，DE440s 计算值系统性晚约 14 秒（2023-12 大雪、2024-01 小寒则完全一致），差异来自不同机构的星历 / ΔT / 岁差章动模型口径。因此默认容差设为 120 秒：此范围内出生会被标为「交节临界」并列出两种可能，而不是悄悄择一。1972 年前的 UTC 与未来年份的 ΔT 本身也有数秒至数十秒的不确定度。

## 重要限制

1. 节气边界必须有可靠的实际交节时刻。不知道就应停止，不可用「2月4日左右」替代。
2. 原始输入要有时区偏移；日界和时钟政策要明确。若当地曾实行夏令时（如中国 1986–1991 年），须先自行换算为标准时再输入。
3. 一切传统格局规则在当前版本都是**初筛候选**，不是完整成格判定或人生吉凶结论。
4. 大运可以在明确指定 `luck_direction` 后排序；只有显式声明 `luck_policy` 与 `gender` 时才推导顺逆和起运年龄。
5. 对于原文与后世注解分歧，应保留多个规则版本，不应自动融成所谓标准答案。

6. `子平八字_AI公式书_V1.0.pdf/.docx` 仍为 V1.0 版本；V1.1 的变更以 `.md` 公式书第十二章为准。

## 网站部署（fpd.xiejiaxue.com）

`site/` 为纯静态站点（Cloudflare Workers Static Assets，Worker 名 `fpd-bazi`）。网页用 Pyodide 在访问者浏览器中运行与测试同一份 `bazi_engine.py`，出生资料不上传服务器。

```bash
python3 site/build.py                                   # 先跑全部测试，通过后把引擎、规则、交节表复制到 site/public
cd site && npx wrangler deploy --domain fpd.xiejiaxue.com
```

`site/public/engine/manifest.json` 记录引擎版本、规则版本、文件指纹与测试结果，网页底部会显示。
